# 戰績上傳、歸屬與分析契約

本文保留既有產品契約, 供相關修改時按需查閱；實作協議另見 [Architecture](../Architecture.md), 介面依 [Style](../Style.md)。原文的版本、驗證及「尚未部署」敘述是當時紀錄, 不代表目前遠端狀態；現行同步方式見 [GAS 發布流程](legacy-gas/gas-release.md)

## 已確認戰績上傳規則

- 管理導覽 `#/battle-upload` 與總覽提供戰績上傳入口, 登入後才可上傳／讀取／下載；管理行事曆戰鬥詳情可開啟並預選場次, 公開行事曆不提供管理上傳。
- 上傳頁選擇已建立的約戰／幫戰／龍虎戰, 日期與類型沿用活動, 不另填日期或時間。約戰與幫戰提供第一場／第二場兩個上傳區, 龍虎戰只有一個；每場最多一個 UTF-8 CSV、1 MB, 約戰／幫戰可按底部各場的上傳按鈕單獨送出任一場, 另一場的待上傳資料保留, 也可由底部「上傳戰績」按鈕一起上傳。幫戰單場週只上傳一場即可, 雙場週各場有獨立隊名／對手及結果, 不共用或覆寫。已指定場序的戰績每活動每場只能一筆, 已上傳區只顯示摘要, 下方分場表格直接顯示已保存資料, 不提供逐場查看按鈕或 CSV 覆寫；切換活動須確認清除未上傳資料。舊未指定場序記錄保留, 不依時間推測。
- 紅方／藍方隊名由 CSV 隊名與人數摘要帶入且可修改, 第一段玩家表頭為紅方、第二段為藍方；2026/10/19 使用者確認以實際玩家列數匯入，摘要人數高於或低於明細時在對應待上傳卡片顯示提醒，不拒絕匯入或刪減／補齊玩家列。原始 CSV 不改寫，前端與本機／GAS 共用解析規則；無摘要或人數一致不顯示提醒，格式／數值／編碼／大小及筆數上限仍檢查。支援 BOM／引號／千分位及舊無摘要格式, 玩家欄位參考 NSHM_history GameDetail 的十二項資料, 缺少焚骨與空數值為 null, 不推測職業、UID 或修改名冊。
- 「我方是哪邊」及「獲勝方」皆選填, 預設空值, 有值時只接受紅方／藍方, 不從空城、傷害或擊敗自動判定。約戰第一場／第二場各有獨立「是否為內推」開關, 預設關閉, 開啟隱藏敵我／勝方並以 null 保存, 切回保留尚未送出的選擇；保存 is_internal 並於已上傳區／下方表格標示內推。幫戰／龍虎戰不提供開關且不能保存內推。一般結果未填不顯示任何一方獲勝, 舊 winner／our_side 及 requestId 保留相容。
- 戰績上傳只提供 CSV 與對戰資料, 不提供陣容圖片上傳；陣容由所選場次的戰場排表查看。原始 CSV 與玩家戰績保存於本機 SQLite, 場次資訊保存快照；舊圖片資料與附件下載保留相容, 不自動刪除。
- 兩檔採整批交易及 requestId 重試, 相同戰績不重複保存；後端重新檢查有效場次／類型／日期。失敗保留全部輸入, 成功才清除待上傳資料。上傳頁下方「戰績資料」使用第一場／第二場 tab, 未保存顯示待上傳 CSV 預覽, 已保存直接讀取該場玩家快照, 提供 20 筆分頁及原始 CSV／舊圖片下載, 不查詢或顯示全部歷史列表；修改／換檔／移除即時更新, 底部集中送出及成功／失敗提示。已保存資料依所選 tab 讀取並快取, 提供載入／失敗／重試與過期回應保護, 不顯示玩家 UID；不提供活動安排捷徑或詳情對話框。
- `battle_uploads` 保存請求／附件, `battle_records` 保存逐場資料與玩家 JSON；場序與敵我欄位追加, 舊勝方必填約束以備份後交易調整, 不更動名冊或排表。GAS 資料／Drive 附件及個人分析已生成，尚未部署驗證；影片連結支援本機及 GAS（見場次影片規則）。

## 已上傳對戰資訊編輯

- admin／manager 可在已上傳卡片及戰績詳情開啟「編輯對戰資訊」，修改紅／藍方名稱、我方、勝方；約戰可逐場切換內推，幫戰／龍虎戰不可設內推。member 維持唯讀。
- 內推保存時清除我方／勝方，第一／第二場獨立；切回一般對戰可重新選結果，未知勝方仍顯示結果未填。CSV、玩家快照、成員關聯、活動快照、日期／類型／場序及原上傳防重複雜湊不變；已刪活動或舊未指定場序的戰績仍可修正資訊。
- `PATCH /api/battle-records/:id`／GAS `updateBattleRecord` 在後端檢查管理角色、CSRF、欄位白名單、revision 及 requestId。SQLite 交易保存資訊及重試結果，GAS 沿用 script lock／提交標記；舊 revision 初值 0，相同請求可安全重試，並行衝突需重載。
- 傳錯的戰績由 admin／manager 刪除後重傳：本機 `DELETE /api/battle-records/:id`、GAS `deleteBattleRecord([id, revision])`（列入 WRITES）。刪除戰績、玩家快照、成員連結與成員參照覆寫，個人戰績與統計同步移除；Drive 原始 CSV／圖片與上傳重試紀錄保留作備份（圖片可能兩場共用）。紀錄不存在回傳 deleted，revision 不符回 REVISION_CONFLICT。測試見 `tests/battle-delete.test.js`。
- 視窗每次開啟讀取最新資料，提供載入、失敗／重試、儲存失敗保留草稿及離開提醒；成功更新卡片／詳情與快取，不影響另一場待上傳 CSV，個人分析及清單重讀使用最新結果。

## 已確認戰績閱覽規則

### 進攻／防守分析

- 對戰詳情提供「進攻分析」及「防守分析」兩個入口，member／manager／admin 可讀。進攻四頁：團比較、進攻團個人明細、機動團個人明細、未分類設定；防守六頁：團分析、防守1–4、未分類設定。attack 三隊為進攻團、mobile 三隊為機動團，防守四隊各自分析。
- 比較頁固定兩張表：「各團／隊數值」及「各團／隊占全場％」，每列一個團／隊及真實人數、每欄一個指標，進攻兩列、防守四列；不再每團一張表或重複「本團合計」字樣。個人明細保留原始數值、團內％及全場％，不顯示 UID。
- 防守配對由比較組 A 選兩個不同隊，B 自動取其餘兩隊，兩組互斥且四隊各出現一次；預設 1＋2 對 3＋4，支援 1＋4 對 2＋3 等組合。選取未滿兩隊時提示，不產生誤導圖表。圓餅圖以目前兩個比較組合的合計為分母，與表格同陣營全場分母分開說明。
- 依詳情載入時、關聯活動最後保存的排表快照分團，顯示保存時間；戰績未固定排表版本，重載詳情才取得新排表，未保存草稿不參與。排表日期／類型不符、未關聯活動、未指定場序、無排表均不推測，列未歸類；已刪活動仍可讀最後排表。
- 第一場取第一人，第二場取明確第二人，未指定第二人沿用第一人。後端優先以既有 memberUid 對應 UID，無關聯才使用唯一精確快照姓名；同名／UID 重複或同一人對應多筆 CSV 不猜測，已關聯他人不因姓名轉移。只分析實際 CSV 玩家，不用未出場排表人員補零。
- 紅藍分開計算，團內分母只含本團實際玩家，全場分母包含同陣營未歸類，內推亦不混用紅藍。進攻指標：塔傷、承傷、人傷、擊殺、助攻、重傷、治療、化羽／清泉；防守：人傷、擊殺、助攻、資源、重傷、治療、化羽／清泉。缺值不作零，部分合計標示；分母缺值、分子部分資料或合計為 0 不顯示誤導占比，重傷不判定好壞。
- `GET /api/battle-records/:id?includeTeamContext=true`／GAS `getBattleRecord(id, { includeTeamContext: true }, context)` 在原詳情同次讀取交易回傳最小分團對應：recordId、排表保存時間、playerIndex／teamId／teamName／原因。不含排表 UID、報名 ID、備註、職責、未出場名單或整份排表，不新增表或放寬 member 排表管理權限。
- 身分對應留後端，合計、比例、排序、分頁、配對及圖表由前端以當頁原始快照計算；開啟／切頁／換陣營／配對不新增 API，只有顯式重載詳情更新資料。詳情仍為 READ_ONLY、無寫入鎖／Drive。首載仍須讀排表與索引，不宣稱消除 Sheets 成本；省略選項保持原詳情契約，舊 team-analysis／getBattleTeamAnalysis 四團 API 保留相容但新 UI 不使用。
- 個人明細支援名稱／職業／數值排序，原未分類玩家在最後的未分類設定頁列出，含名稱／職業／原因排序；缺值永遠置尾，先排序再每頁 20 筆，切陣營／團別回第一頁。合計不受明細排序或分頁影響。失敗可重載，拒絕過期回應，關閉回入口焦點；手機表格容器橫向捲動。
- 未分類設定僅前端：以原CSV playerIndex指定進攻團／機動團／防守1–4，保持未分類可逐列還原，另可清除全部。兩分析共用且每列最多一組，紅藍隔離；只能補原未分類列，不改自動對應、不創建成員或轉移數據歸屬。合計／團內比例／占全場比例／防守配對與圖表使用臨時結果；全場分母不變、缺值沿原規則。設定頁保留已指定列及原原因供調整，明細標臨時，無排表仍可手動分析但保留來源警示。
- 臨時分隊僅當頁記憶體，關閉重開／切進攻防守／跨頁保留；新詳情快照、換紀錄或卸載清除，不存localStorage／URL／後端。分類重算只依來源與指定變動，切tab／頁碼不重算；設定與清除零新增RPC、零寫入鎖。
- 圓餅圖只載必要 ECharts 模組，以單一 Canvas 實例顯示多指標、無非必要動畫，合併更新並清理 ResizeObserver／排程／實例；明暗及手機適配。網站延遲載入，GAS 單檔仍需傳輸圖表程式，不把動態 import 當成零下載成本。

### 清單與詳情

- 對戰詳情玩家表格依內容分配欄寬，不用比頁面還寬的固定min-width；短次數／職業縮減左右留白，傷害及姓名保留空間。常見兩位數擊敗／重傷／焚骨／化羽清泉、三位數助攻、四位數資源僅供版面參考，不限制或截斷更大值；一命、排序、字級下限、手機容器捲動與固定姓名需保留。不為欄寬額外讀表或逐格JS量測。
- 管理導覽及總覽提供 `#/battle-records`, 清單每頁 20 筆, 點擊對戰開啟 `#/battle-records/:id`；清單與詳情都須登入, 直接連結登入後保留目標記錄, 支援重新整理與返回。
- 詳情上半顯示保存的日期／類型／場序／雙方名稱／結果、雙方人數及職業分布, 比較十項數值合計與差距；缺值顯示「—」, 部分缺值標示部分資料, 不把缺值算作實際零值。
- 下半紅／藍方分頁顯示十二欄戰績, 資源欄在最右, 提供本筆快照職業篩選與總計／一命模式；一命採原數值 ÷ max(重傷次數, 1), 重傷欄保留原次數, 缺少原數值或重傷不換算。名稱／職業與當前模式數值可升降排序, 用未四捨五入值先篩選／排序完整資料再每頁 20 筆, 缺值永遠排最後, 變更陣營／職業／模式／排序回第一頁, 不顯示 UID。上半統計不受表格條件影響。
- 敵我／勝方使用原保存值, 未填與內推保留原狀, 不依玩家、人數、隊名推估類型或勝敗；舊未指定場序、未關聯活動及已刪活動的戰績仍可閱讀。統計與玩家表格讀取既有快照；管理者可另外修改對戰資訊，不修改玩家數據、名冊或排表；GAS 已生成對應資料功能，尚未部署驗證。

## 上傳前成員身分與數據歸屬

- 只供 admin／manager 的待上傳預覽；每列以文字標籤顯示幫會／俱樂部／兼屬／編外／未匹配，同名標示待確認，未知不等於外援。進頁背景讀一次 getBattleUploadRoster／GET /api/battle-upload/roster，只回內部 UID、姓名、revision、兩個所屬狀態及主職業文字，不顯示 UID。
- 名冊未完成或失敗不阻擋 CSV 解析／預覽／依原角色上傳，歸屬調整等成功後啟用。重試／手動重載取新名冊，離頁忽略舊回應；當頁分類／選人／跨頁與雙場重用快照，不跨請求快取授權或 revision。
- 「調整歸屬」才開成員搜尋；A 操作 B 時指定 A 的 UID，優先於原角色 B 的自動比對。顯示 A 並保留原角色 B，不修改名冊或新增永久別名；沒有自由輸入任意名字。已上傳歷史不提供更正入口。
- 歸屬草稿以檔案／場序／原始 playerIndex 保存，跨頁／雙場各自保留，換場／替換或移除檔案清除相依內容；同成員多列警示但不合併／刪列。清除指定回復原自動匹配。
- 歸屬與原上傳同次提交，不逐列保存。兩平台以來源角色／陣營與索引驗證原列，最終交易核對指定成員姓名／revision；失效要求重載確認並保留草稿。數值／職業／陣營及 CSV 不改，creditedName 只是顯示快照，個人頁依 links 計入 A。
- 指定歸屬參與 requestId 指紋，但不改原 CSV 重複識別；相同未知結果沿同內容／requestId 重試，不因換歸屬重複匯入。GAS 新名冊只讀不取業務鎖；保存沿原最終 Script Lock／commits／flush，不新增鎖、表或通知。

## 個人戰績

成員清單（含編外人員）提供「查看數據」；戰績閱覽中已關聯的人名可開啟 `#/member-records/:uid`，已登入 member／manager／admin 均可使用。UID 只作路由及內部引用，頁面、名稱、標籤與 title 不顯示。未關聯人名保持純文字。

未手動指定歸屬的戰績列，在上傳的同一交易以當時名冊現在名稱精確比對，包含編外；唯一符合才保存 UID，不以職業、敵我、過去名稱或模糊搜尋推測。同名／未知名稱不關聯。`battle_player_links(record_id, player_index, member_uid)` 使用外鍵、逐列唯一索引及 member_uid 查詢索引，保留不可變的 players_json、原始 CSV、requestId／content_hash；詳情回應在讀取時加入 memberUid。單筆新增與 CSV 匯入共用成員建立流程；新增後依現在名稱精確比對尚未關聯的歷史玩家列，唯一同名才寫入關聯，已歸屬他人的資料不轉移。CSV 先完成整批建立再判斷唯一性，包含既有及同批同名；成員與關聯於同一 SQLite 交易／GAS 提交中保存。既有 UID 匯入仍跳過；改名、移至編外及重啟不觸發回填。原始 CSV、玩家快照與請求雜湊保持不變，戰績重試不重新比對名稱；本機詳情與重試讀取最新關聯，GAS 已保存的重試回應保持原樣。

`GET /api/members/:uid/battle-records?page=1&startDate=2026-10-01&endDate=2026-10-31&profession=碎夢` 支援選填的台北起訖日期（含當天、可只填一邊）與當場職業名稱。日期須為有效 YYYY-MM-DD、結束不得早於開始；職業依不可變玩家快照精確篩選，選項涵蓋該成員全部已關聯紀錄。回傳現在名稱／職業、篩選條件、職業選項、全部符合條件參戰的統計，以及每頁 20 筆最新優先明細。包含保存的場次類型、日期、場序、當時姓名／職業、陣營、對手與十二欄數據，點日期可回對戰詳情。無資料、找不到成員、載入／失敗／重試均有提示，直接連結登入後保留目標。

個人統計提供參戰場數、勝／敗／內推或未判定場數、十項合計、每筆平均及一命貢獻。平均僅使用各欄已知數值；一命貢獻使用有該欄數值及重傷的紀錄合計，除以這些紀錄各筆 max(重傷, 1) 的總和；重傷欄仍保留合計。缺值顯示 — 並標示缺少筆數，不當作 0。不依隊名或其他數據推測勝敗，內推及結果未填不計勝敗。同場重複玩家列均保留且場數只計一次；兩邊結果衝突時歸未判定。明細可切總計／一命，資源維持最右。個人頁統計依已勾選且符合篩選條件的紀錄，不受明細分頁影響。套用或清除條件回第一頁，無符合資料明確提示，原有 member／manager／admin 讀取權限不變。舊分頁 API 仍回傳全部符合條件的摘要，GAS `getMemberBattleRecords` 維持相同相容契約。

v1.0.21 個人頁首次／手動重載以 `all=true` 一次讀取該成員全部已關聯玩家列，不分批逐頁追讀；HTTP 選項只接受 true／false 字串，GAS 選項須 boolean。此模式回傳完整 entries／total／professions，不計算或回傳後端 summary，統計留在前端；省略 all 仍為每頁 20 筆加完整摘要。GAS 先整理該成員的場次索引，僅 getMany 有關聯的 battles／battle_players，不讀無關場次 payload 或 Drive；保留唯讀快照、登入權限及不取得寫入鎖的行為。仍須掃描提交／索引與成員關聯，首載時間及回應大小會隨個人歷史成長，沒有跨請求快取或資料搬移。

前端預選最新 10 筆（依日期、建立時間及原有穩定次序），以 recordId／playerIndex 獨立勾選。同場兩筆可分別選取，場數去重；換頁保留勾選，篩選只取已選與符合條件的交集，清除篩選恢復原勾選。表頭選本頁，不提供最新 10 筆／全部符合／清除勾選三顆快捷按鈕；重載保留仍存在的選取，換人重設並丟棄過期回應。篩選、分頁、統計模式、勾選與走勢指標都不重新呼叫後端。

擊殺效率採 `playerDamage / kill`，單位傷害／人，零擊敗或缺任一欄顯示 —；總覽只取兩欄完整紀錄，以傷害合計／擊敗合計，包含零擊敗紀錄的傷害，缺值筆數另列；不平均各場比率且不隨合計／平均／一命切換。ECharts 6.1.0 只註冊折線、座標、Tooltip、縮放及 Canvas，圖表由舊到新、缺值斷線、明暗主題、關動畫／LTTB／實例重用／ResizeObserver 與卸載清理。圖表改由「查看走勢」開啟右側抽屜，桌面最多 960px／92vw、手機全寬；精確數據沿用主頁各場戰績，不再建立重複表格。首次開啟才載入／初始化，關閉保留指標與實例，隱藏不重算／繪圖，重開校正尺寸；Escape／遮罩／關閉與返回按鈕皆可關閉，焦點返回入口並保留捲動。一般編譯圖表於首次開抽屜延遲載入，GAS 單檔仍必須一起打包。

## 成員戰績閱覽權限

已登入 member／manager／admin 可使用戰績清單、對戰詳情、原始 CSV／既有附件下載及個人數據分析。各角色的導覽皆提供「回首頁」返回行事曆，member 另顯示成員清單與戰績閱覽，點左上平台名稱亦可返回，從對戰表格點已關聯人名可開啟個人頁；成員清單開放 member／manager／admin，「移至編外」按鈕及端點僅供 admin／manager，其他管理功能仍只供 admin／manager。共用 member 通行密碼不綁遊戲 UID，因此可查看所有已關聯成員的數據，不限制為本人。匿名不可讀，member 不可上傳／修改戰績、活動、排表或帳號。後端分別放行明確戰績 GET 路徑及成員清單的讀寫路徑／方法，不以 URL 前綴放寬其他管理操作。

桌面不論可見戰鬥入口幾個都保留「戰鬥」群組，使用已依角色過濾的items；member只見數據分析，admin／manager保留戰場排表／上傳數據／數據分析。手機同樣以戰鬥小標分類且隱藏member管理入口。不要將仍帶group標記的單一入口當作普通項目，避免選單模板誤讀不存在的items。詳情「編輯對戰資訊／刪除戰績」只供admin／manager，member不顯示且後端拒絕直接呼叫，成功可讀不代表可修改／刪除。

右上登入視窗包含「成員登入」「管理者登入」兩個 tab；前者只填 admin 發行的通行密碼（英數 6–128 字），後者沿用 Manager／Admin 帳號密碼。共用視窗一律預選成員登入，首頁登入後留在行事曆，直接開啟戰績／個人分析或管理連結成功後保留原目標及權限；切換 tab 清除密碼及登入錯誤。

## admin 歷史戰績同步

- 帳號管理的「資料維護」分頁提供「同步歷史戰績」，僅 admin；manager／member 不能預覽或確認同步。預覽比對全名冊（含編外）的現在名稱及 member_name_history／GAS name_history；只有唯一 UID 的精確同名才補上尚未歸屬的玩家列。
- 同一 UID 的重複現名／舊名去重；名稱跨 UID 重複（包含現名／舊名及舊名／舊名）均列為同名衝突並跳過，不優先猜測目前名稱。已綁定或快照已有 memberUid 的資料不轉移，原始 CSV／玩家數據／上傳雜湊不改。
- 預覽列出戰績名稱、現在成員名稱、現名／過去名稱及筆數，另有同名跳過分頁；20 筆分頁，不顯示 UID。CSV 未保存 UID，名冊或歷史未記錄的舊同名者仍無法辨識，須由管理者核對預覽。
- 確認時重新計算 fingerprint，名冊名稱／歷史／待關聯戰績有變動即要求重新預覽。requestId 重試返回原成功結果；SQLite battle_sync_requests 與關聯採同一交易，GAS 沿用 GM_requests／GM_battle_links、script lock 及提交標記。
- `GET /api/admin/battle-sync/preview`／GAS `previewBattleMemberSync` 只讀；`POST /api/admin/battle-sync`／GAS `syncBattleMembers` 檢查 admin 角色及 CSRF，不接受前端指定歸屬。失敗保留預覽及重試識別，送出時停用重複操作、重讀與關閉，關閉返回入口焦點。
- 新增／匯入及上傳的既有自動關聯仍依現在名稱；改名、匯入既有 UID 與啟動不自動補關聯。本次手動同步處理舊版本成員與舊名戰績。
