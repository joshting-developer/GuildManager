# 成員名冊與維護契約

本文保留既有產品契約, 供相關修改時按需查閱；實作協議另見 [Architecture](../Architecture.md), 介面依 [Style](../Style.md)。原文的版本、驗證及「尚未部署」敘述是當時紀錄, 不代表目前遠端狀態

## 已確認成員規則

- 成員名冊提供 CSV 匯出：沿目前成員／編外分類及所有篩選，輸出全部符合資料（非僅當頁），依原清單順序包含 UID、名稱、主副職業、幫派／俱樂部狀態與過去名稱；缺值留空，不輸出操作或內部版本。沿用完整名冊 admin／manager／member 權限，前端只重用當頁已授權資料，不新增 API、快取或鎖。CSV 共用 tableCsv 的 UTF-8 BOM／CRLF／引號與公式防護；下載 URL 延後回收及卸載清理。此為閱覽格式，既有四欄匯入契約維持不變。
- UID 是文字主鍵，名稱及主職業必填、副職業可空；一般編輯維持 UID 鎖定，admin／manager 可透過專用維護功能修正 UID（見成員資料維護）
- UID 僅在成員管理清單及相關表單／匯入／歷史視窗顯示；報名、排表、排表歷史、範本提示與 title 不顯示玩家 UID, 內部關聯與快照仍保留 UID
- isInGuild／isInClub 為獨立 boolean, MySQL is_in_guild／is_in_club 保存 0／1 並有 CHECK 約束。
- 名冊分成成員／編外人員 tab：成員至少一個所屬狀態 true, 編外兩者 false；成員頁提供俱樂部／幫派／不篩選, 與名稱／職業條件交集。
- 成員及編外均可獨立篩選主職業與副職業，副職業含「無副職業」，未選表示不篩選；和搜尋／所屬條件取交集，變更條件回第一頁，清除同時重設兩種職業且保留目前分頁。
- 成員頁新增與四欄匯入新 UID 預設幫派內 true、俱樂部內 false；編外頁新增預設兩者 false, 可編輯調整。
- 舊資料初次新增狀態欄位時依先前在會狀態初始化幫派內, 俱樂部未記錄初值 false；舊 removed_at 紀錄轉為兩者 false 的編外人員並增加 revision, 保留資料與歷史。重啟不重設已修改值。
- 編輯省略新欄位時保留原值, 有傳值時必須為 boolean；狀態變更更新 revision, 不新增名稱歷史。
- 四欄匯入既有 UID (含編外) 跳過且保留狀態；編外回歸使用編輯勾選任一所屬狀態, 不建立重複 UID。
- `professions(job_id, colorcode, name)` 保存使用者提供的九個職業, 名稱採最新提供的「神相」
- 前端選單讀取職業 API, 成員以職業 ID 關聯, 未來擴充資料列不需改選項
- `member_name_history` 用 UID 關聯, 改名與寫入歷史使用交易, 職業修改不產生名稱歷史
- 原移除操作改為「移至編外」, 只將兩個狀態改為 false, 保留資料與名稱歷史；removed_at 只作舊資料相容, 新操作不再設隱藏標記
- 編輯與移至編外檢查 revision, 不覆寫其他人的新版本
- 匯入欄位順序 UID、Name、主職業、副職業, 職業填名稱, 可用 UTF-8 CSV／TSV／TXT 或貼上文字
- 匯入先預覽, 既有 UID (含編外) 跳過不覆寫, 新增成功後彈窗顯示新增／重新加入／跳過筆數
- 匯入內有格式或重複 UID 錯誤時整批拒絕, 確認需檢查預覽版本, MySQL 寫入使用同一交易
- 一般本機驗證使用隔離 MySQL, 不自動播種假成員或寫入正式資料。需要示範資料時用 `npm run seed:demo` 手動新增 100 位示範成員：80 位幫派兼俱樂部、20 位僅俱樂部, 示範 UID 固定且已存在時跳過, 不覆寫既有資料。

## member 成員清單權限

member／manager／admin 均可進入 `#/members`，成員與編外分類、UID、過去名稱、主副職業／所屬篩選及查看數據皆可使用；新增、修改、匯入預覽／確認維持既有權限；member 隱藏「移至編外」按鈕，該端點僅供 admin／manager。UID 仍只在成員管理清單及相關表單／匯入／歷史視窗顯示，其他頁面規則不變。

本機允許有效 member session 呼叫成員清單對應 GET／POST／PATCH 路徑；`DELETE /api/members/:uid` 僅 admin／manager 可用；一般編輯所屬狀態維持現況，不額外限制。寫入維持 CSRF、格式、revision 及匯入版本檢查；共用 member 帳號角色不變，不綁本人 UID。其他管理總覽、活動、排表、戰績寫入、影片／出勤閱覽及帳號／平台設定沿用原權限。匿名仍不能讀寫完整名冊，通行密碼變更撤銷 session 後不能操作。

## 成員資料維護（2026/10/19）

- admin／manager 可永久刪除錯誤資料、修正 UID 及新增／修改／刪除過去名稱。member 保留所有既有名冊功能，但不開放這三項維護操作；清單隱藏入口，Node 後端均檢查角色，不能用一般 updateMember 傳 UID 繞過。
- UID 編輯預設 disabled，管理者在編輯視窗開啟「開啟 UID 修正」才可修改；不能覆蓋既有 UID。名稱、職業與所屬狀態可一起保存，改名仍自動記錄舊名；UID 修正同步歷史、場次回應、戰績關聯及已保存排表／範本的有效引用。
- 過去名稱管理每次開啟讀最新資料，可在現在姓名不變的情況下補舊名、修正錯字、移除錯誤紀錄。既有紀錄保留記錄時間，新紀錄保存新增時間；新增或修正名稱不可與現在名或其他舊名重複，既有自動改名造成的重複舊名可原樣保留。不自動轉移既有戰績，沿用 admin 戰績同步預覽核對同名衝突。
- 永久刪除與「移至編外」分開，須輸入完整 UID 確認；移除名冊、過去名稱、場次報名／請假及戰績 UID 關聯，保留整場原始 CSV、玩家數值和排表姓名快照，不刪整場排表或外援資料。
- 新維護讀寫使用 GET／PATCH `/api/members/:uid/maintenance`、PATCH `/api/members/:uid/history`、POST `/api/members/:uid/permanent-delete`；寫入檢查 CSRF、revision、requestId 及欄位白名單，成功請求可安全重試；過期畫面要求重新載入，失敗保留草稿，送出只顯示一個轉圈。
- 不改不可變排表／CSV JSON；`member_reference_overrides` 保存逐紀錄 UID 對應, 讀取時套用, 不作全域舊 UID 轉址；刪除後引用變 null、姓名快照保留；UID 再利用不使舊引用復活。另保留 UID revision 下限，重建或移入曾使用的 UID 時版本遞增，舊畫面不能操作新人。
