# GAS 效能與併發契約

本文保留既有產品契約, 供相關修改時按需查閱；實作協議另見 [Architecture](../Architecture.md), 介面依 [Style](../Style.md)。原文的版本、驗證及「尚未部署」敘述是當時紀錄, 不代表目前遠端狀態；現行同步方式見 [GAS 發布流程](gas-release.md)

## 效能與併發開發規則（後續功能預設適用）

以下是已驗證優化的常態要求；新增功能、修改及 review 都需檢查，不能只留在版本交接。計畫記錄本次的讀寫範圍、預期請求次數、快取生命週期及鎖需求；不適用的策略由實作證據說明取捨，不為套用規則擴張使用者需求或重構無關功能。細節見 [Architecture.md](../Architecture.md#gas-最新已提交版本讀取v1020)、[GASConcurrency.md](../GASConcurrency.md#v1019-實作結果已同步-gas尚未更新部署) 及 [Style.md](../Style.md)。歷史盤點與舊版待辦不是目前實作要求；交付狀態以 [GASDeployment.md](../GASDeployment.md) 最新狀態為準。

2026/10/27 的官方文件、開發者實務與後續可行性研究見 [GASPerformanceSurvey.md](../GASPerformanceSurvey.md)。其中 batchGet、最新排表目錄、通知 outbox 等是待量測／待選定的提案，不是已實作或可直接套用的現行規則；採用後須另補驗證與協議。

### 資料載入與快取

- 優先減少 GAS／Sheets 往返，再評估 CPU 計算；同一表單需要且須一致的名冊、職業與回應，在同次讀取交易組裝並重用，避免各元件重複 RPC 或逐筆查詢。
- 分析頁若需要反覆篩選／勾選，且該成員或場次的完整資料量合理，優先一次讀取該範圍的已授權資料，篩選、排序、分頁、統計及圖表切換由前端處理。不能因此載入全站歷史或無關玩家快照；資料量、敏感範圍或新鮮度不適合時，保留後端查詢／分頁並記錄理由。當頁只用前端統計時，後端避免再計算用不到的整份摘要，保留舊呼叫契約。
- 匯入前的身分標示可背景讀一次管理者精簡名冊，以當頁 Map 做分類／搜尋，不逐列 RPC；慢速／失敗只標示未確認，不把未知直接判成外援。手動數據歸屬必須保存真實成員引用及來源列／成員版本，在最終寫入保護內重驗；保留原角色、數值及原檔，不藉改名或永久別名轉移數據。
- 分析需排表／身分對應且詳情尚未包含時，後端在同次已授權讀取帶最小必要對應，再由前端重用原始快照計算；不傳整份私人排表、不複製計算用不到的伺服器摘要，保留舊 API 契約及顯式重載的新鮮度。
- 版本快照若每次另存不同 ID，storage 的「只解碼每 ID 最新提交」不會自動只取最後一份業務快照；介面只用最新一版時，repository 先選最新版再投影／回傳。範本等次要清單延後首次操作載入摘要，完整配置只在實際套用讀取；來源更新不得順便重載用不到的歷史或範本。
- 公開資料若各角色可見範圍相同，可與登入確認並行載入／呈現；只在該公開介面解除等待，不取消管理入口的登入門檻或送出時 CSRF／身分／版本驗證。資料用途縮小時提供精簡讀取且保留舊 API，不為隱藏統計而移除報名身分辨識與併發所需的回應版本。
- 整併讀取已包含初始選項與詳情時，套用結果不得因 v-model／watch 再觸發同一筆查詢；可用明確的使用者選擇事件區分載入與互動。顯式重新載入若承諾最新清單，不能無意沿用一般導覽的短期快取；讀取範圍、快取熱／冷差異需記錄。
- 只讀目前成員／場次／紀錄需要的內容；摘要與大型詳情分開，詳情按需載入。保存成功只更新受影響資料，避免重載整份名冊或全頁；顯式重新載入應取得最新資料，換人／換場／卸載須丟棄過期回應。
- 清單與詳情共用當頁快取時，編輯成功須以已驗證回應更新對應列，刪除須使清單失效並補齊分頁／校正末頁；純查看返回仍可重用。變更成功須淘汰較早的進行中清單讀取，避免舊回應蓋回新資料，並恢復仍存在的入口或合理備用焦點。只編輯摘要時可另提供最新 revision 的精簡唯讀，不為省讀取沿用舊 revision。
- 可重用同次交易的索引、解碼值、查無結果與中間集合；職業等低變動資料可共用同 transport 的進行中／成功請求，失敗後允許重試。跨請求或瀏覽器快取必須定義來源／權限範圍、失效及登出處理；不得把變動的報名版本、revision 或授權結果當作長期可信快取。快取失敗不阻止正常操作。

### Sheets 儲存與查找

- 沿用 storage／repository 介面、固定 ID、批次讀寫；避免逐格呼叫、迴圈內重取 getLastRow 或每個位置重找整份名單。多次查找使用可隨來源失效的 Map／Set，同次查詢重用關聯分組與已排序清單；小型一次性查找不為形式額外建索引。
- GAS 讀取須固定本次 commits 快照，依提交次序挑最新已提交版本，再驗證分段與解碼；不可依實體列次序推測最新。最新損毀必須報錯，不退回舊值；刪除標記、重建及本交易 staged 修改保持正確。
- 保留目前指定 key／大表先讀四欄索引、再批次讀最新 payload，小表 all 使用一次五欄讀取但只解碼最新版本的取捨。128 個資料列是目前策略門檻，含歷史與分段、不含表頭，不是容量上限或所有表的效能保證；調整須比較往返、傳輸及解碼量。
- 保留五欄／Base64 分段、完整歷史、flush 與提交標記，不以效能為由直接改寫／刪除歷史、改 schema 或執行正式初始化。索引與 commits 仍會掃描，分散的最新列可能增加範圍讀取，不能把只解碼最新版本說成完全不掃描歷史。

### GAS 鎖、版本與重試

- 純讀取優先走嚴格唯讀快照並保留登入／角色檢查，不取得業務寫入鎖；新 RPC 須盤點完整讀寫依賴後才加入 READ_ONLY 白名單，不能只憑 get／preview 名稱解鎖。唯讀路徑禁止 put／remove／建表／保存登入狀態；缺表初始化須隔離，在必要寫入鎖內重新驗權後執行。
- 寫入依共享資源判斷鎖需求，不能因業務表不同就拆鎖。共用 commits、requests、同表 append 及登入狀態讀改寫仍需互斥；revision／唯一性／requestId 檢查與提交須在同一保護範圍。登入讀取保留穩定指標檢查及有限次重讀，不移除既有撤銷或限流保護。
- 純解析／可重用計算與獨立私人 Drive 建檔應盡量在鎖外準備；取得最終寫入鎖後須重讀最新快照，重驗權限／CSRF、來源版本、唯一性及 requestId 才提交。通知在提交並釋放鎖後發送；不得把慢 I/O 或等待重試重新放回寫入鎖。跨服務未引用檔案保留既有復原策略，不擅自自動清理。
- 版本檢查應覆蓋真正相依的資料；已辨識不同成員的獨立回應使用個人版本，避免整場版本造成無關衝突，同人／身分／場次變更仍阻止覆蓋。舊 API、未知或同名直接輸入保留相容與驗證，不為降低衝突移除檢查。
- 只對能確認尚未執行業務操作的 BUSY 作有限退避重試，沿用共用 adapter 的最多三次、350／700ms 加隨機延遲及原 payload／requestId／context；不新增重複重試迴圈。未知傳輸結果、版本或授權錯誤不盲目自動重送；回應遺失的寫入由原 requestId 安全重試，不能換新 ID 重建。

### 前端計算、圖表與等待體驗

- 用 computed 分開資料分類／排序與選取／頁碼等依賴；搜尋或安排成員時不要重排不變來源。大型不可變快照可用 shallowRef 減少深層代理，更新時替換值；不能因此讓仍需追蹤的巢狀編輯失去反應。先篩選／排序完整範圍，再做畫面分頁。
- 分析用的臨時分類以原快照與穩定列索引建立獨立覆蓋層，不修改原始快照或身分對應；定義關閉／重開／重新讀取的保留與失效範圍。設定頁保留原候選列，避免指定成功後消失而無法修改／清除；統計重算沿同一套缺值及分母規則。
- 勾選以穩定 ID 保存，純顯示互動不寫後端或新增資料請求。缺值與未知不得當成 0；合計、平均與比率使用未捨入原值，比率依業務定義處理零分母及完整成對資料，只在顯示時捨入，不直接平均各列比率。
- 圖表僅引入必要模組，重用實例、合併同一畫面更新、避免非必要動畫；抽屜等非必要圖表首次開啟才初始化，隱藏時暫停計算／繪圖，重開保留狀態並校正尺寸。資料量大時評估降採樣並保留精確數據。明細以分頁／按需展開控制 DOM 數量，ResizeObserver、事件與動畫排程在卸載時清理。評估新增依賴及明暗／手機成本；一般網站可延遲載入，GAS 單檔仍計入首載大小，不宣稱動態 import 就免除下載成本。
- 沿用 Style.md 的單一載入提示、提交防重複與失敗保留草稿；重載保留仍有效的選取，不用全頁寫入遮罩阻擋無關操作。報名／請假需優先驗證不同人同舊表單可提交、同人衝突可理解、忙碌重試仍保留內容。

### 優化驗證與規則維護

- 行為不變的效能優化先保留既有測試與 API 契約，再補新舊結果比較及代表性資料量的回歸；不得修改預期值或縮減驗證來掩蓋退化。需求明確變更而必須修改舊測試時，說明被取代的規則並保留其他保護斷言。
- 驗證應涵蓋本次影響的請求次數、相關／無關資料讀取、歷史／分段／缺值，以及權限、同人／不同人、持鎖讀取、部分失敗與相同 requestId 重試。UI 調整驗證桌面／手機、明暗及過期回應；使用隔離資料，不以正式資料進行驗證性寫入。依變更選擇測試，完成必要測試與一般／GAS 編譯；純文件變更只檢查內容、連結及差異。
- 以實際證據區分 RPC、Sheets 讀取、解碼／計算次數、打包大小與 Google 真實耗時；模擬呼叫量下降不等於已量測正式秒數，也不保證所有資料分布都更快。診斷只記必要步驟／耗時／固定錯誤分類，不記憑證、原始 payload 或玩家資料。
- 後續新增可重用優化時，同步補本節的常態規則與適用邊界；實作協議放 Architecture.md，鎖與讀寫依賴放 GASConcurrency.md，介面規則放 Style.md，當次證據及交付狀態由本機記憶索引連到私人歷史紀錄。不要只追加版本歷史，讓下次仍須使用者提醒。
