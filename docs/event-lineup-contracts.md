# 活動、報名、排表與影片契約

本文保留既有產品契約, 供相關修改時按需查閱；實作協議另見 [Architecture](../Architecture.md), 介面依 [Style](../Style.md)。原文的版本、驗證及「尚未部署」敘述是當時紀錄, 不代表目前遠端狀態

## 已確認活動安排規則

- 活動安排清單提供名稱搜尋（忽略頭尾空白與英文大小寫），與類型篩選取交集；變更條件回第一頁，清除同時重設名稱／類型。依每筆首個安排日期由新到舊，同日依建立時間由新到舊；多日安排內日期維持原順序。建立／修改成功清除篩選並定位該筆所在頁，手機搜尋／類型直排。
- 類型為活動 (`activity`)／約戰 (`scrimmage`)／幫戰 (`guild_war`)／龍虎戰 (`dragon_tiger`), 日期必填；活動／約戰名稱必填, 幫戰／龍虎戰名稱可空或省略, 保存空字串。
- 前端未命名安排以類型文字及現有日期顯示, 不回填虛構對手；表單仍顯示原空值。修改／刪除操作按鈕的未命名標籤加入日期, 排表與歷史亦使用顯示回退。
- 活動一筆可選 1–366 天, 約戰恰好一天；幫戰／龍虎戰批次建立可選 1–366 天, 每日期獨立一筆 ID／revision, 編輯每筆只能一天。前端與後端都檢查。
- event_batches／event_batch_items 只用於批次建立防重複, 同一交易建立全部場次, 部分失敗回滾；單場修改／刪除不影響其他日期。
- 幫戰每週、龍虎戰每兩週的需求目前透過手動多選日期建立, 尚未自動生成週期；戰績 CSV 已實作，影片連結支援 Node（見場次影片規則）。
- 日期保存為 `YYYY-MM-DD` 的台北日曆日期, 不以 UTC 時刻轉換。
- 共用安排表單提供行事曆／日期選單兩種模式；切換保留日期，日期選單更改起訖日後選取完整期間（含兩端），最多 366 天。約戰及編輯幫戰／龍虎戰只有單日欄位；無效或未完成的區間阻止儲存，失敗保留輸入，不更動既有 dates[] API／批次規則。
- `scheduled_events` 保存安排, `event_dates` 以安排 ID 關聯各日期, 同一交易寫入。
- 使用 requestId 避免儲存結果不明時重試產生重複安排。
- 管理總覽月曆點日期格開啟共用建立視窗並預選當天；新首頁點有安排的日期格查看當天場次, 約戰／幫戰／龍虎戰提供報名／請假, 不從首頁建立安排。
- 管理行事曆的當日安排視窗, 三種戰鬥顯示本場成員及外援的報名／請假人數, 一般活動不顯示；每次開啟重新讀取, 提供載入／失敗及重試, 不把未知值當 0。
- 管理總覽當日安排視窗與活動安排清單，三種戰鬥提供「出勤閱覽」共用視窗；預設請假，約戰顯示請假／報名兩個 tab 及實際人數，幫戰／龍虎戰隱藏報名 tab。列出名稱、當場職業與備註，不顯示 UID；未回應／舊 none 不計入，已取消外援歸請假，不以排表資格推算。`GET /api/events/:id/attendance` 僅 admin／manager 可讀；一般／已刪場次不可讀。每次開啟重讀，提供載入、空名單、錯誤／重試及重新載入，不以 0 代替未知值，關閉／換場拒絕過期回應並恢復入口焦點。首頁玩家報名視窗維持不展示個別名單。
- 出勤閱覽的請假清單提供管理者「取消請假」，`PATCH /api/events/:id/attendance` 檢查 admin／manager、CSRF 及回應 revision；資料已更新要求重載，相同成功操作可安全重試。名冊成員改回 none，保留所屬狀態、當場職業及備註，幫會／俱樂部成員恢復排表資格；外援恢復原報名 ID 及有效狀態。成員自行請假後再報名改為 registered，同樣解除請假，不新增外援或改變幫會／俱樂部身分。操作期間停用重複操作，成功更新名單，失敗保留清單並提示。
- 建立視窗顯示預選日期所在月份, 成功後更新月曆並保留瀏覽月份；取消後返回原日期格焦點。
- 支援建立、查詢、修改名稱／類型／日期及刪除；場次報名／請假另見下節, 時間與對手未定案。
- 修改與刪除以 revision 檢查版本, 日期替換採同一交易；相同修改或刪除的失敗回應可安全重試。
- 刪除確認列出名稱與影響日期筆數, 成功後移出清單與月曆；MySQL 保存 deleted_at 避免延遲建立請求重建已刪安排。

- 過期影片入口／手動重載使用 GET /api/events/:id/video-form，同一唯讀快照回 event／eventId、必要公開 members／professions，不讀回應／外援／影片／requests／物件儲存；匿名與 member 可讀三種有效單日戰鬥，不加後端過期截止。今日／未來沿用 participation-form。重載回傳最新 event revision，保留影片草稿；日期被改到未來後補讀正常 participation-form，關閉／換場忽略舊回應。跨午夜已有資料可重用，不增加讀取。
- 首頁行事曆三種戰鬥的日期早於台北今天時，入口與視窗只保留「影片上傳」；隱藏報名／請假、職業統計及報名人數，開啟預選影片。今天／未來場次保留原三 tab；一般活動不變。影片名冊／職業沿用原本單次 getForm，不額外增加讀取，切換不清除影片草稿。
- 今日／未來的報名視窗首次／手動重載使用 `GET /api/events/:id/participation-form`，在同一讀取交易回傳原 participation 資料、必要名冊與職業，三種戰鬥均公開。舊端點及回應保留；送出成功後只重讀 participation。交易／CSRF／重試規則不變。
- 約戰／幫戰／龍虎戰均公開可見與操作，未登入亦可報名／請假、選取成員及上傳影片。三種報名的名稱區統一為直接輸入／幫會成員名單（isInGuild）／龍虎戰成員名單（isInClub，含兼屬）三頁，自動帶入主職業且可改，不顯示 UID。狀態只有「報名／請假」，請假不要求職業。
- 公開首頁的場次視窗不顯示報名總人數與職業統計，即使 admin／manager 登入亦相同；管理用行事曆保留報名／請假人數與出勤閱覽。公開視窗不顯示個別報名者清單，送出成功只顯示「報名成功／請假成功」。今日／未來仍讀取身分比對與個人版本所需回應，不將畫面隱藏當作 API 存取限制。
- 公開今日／未來視窗提供報名／請假與影片上傳兩個 tab，過期只留影片；切換保留草稿。共用元件的 showCounts 僅由管理模式啟用，職業統計沿用有效 registered 計數、包含零人，不將 leave／none 計入。
- 後端按名稱精確比對成員或本場報名；幫會／俱樂部成員可直接請假, 編外需已有本場回應, 未知名稱顯示「沒有報名或沒有資料」, 直接輸入同名無法唯一辨識時拒絕並提示聯絡管理者；從名單選擇以內部 memberUid 驗證目前姓名與所屬狀態, 可區分同名, 失效資料要求重新載入。
- 名冊成員沿用 UID, 不新增重複外援或改名冊職業；`event_member_responses` 保存 registered／leave、備註及 revision, 舊 none 保留相容但不在前台顯示。同日多場分開回應, 請假後再報名可回到資格名單。
- 成員本場報名職業保存於可空 profession_id, 外援沿用報名 profession_id；職業統計依本場選擇計算, 舊成員回應未記錄職業時採名冊主職業, 不回填舊資料或更動名冊與排表快照。
- `event_registrations` 獨立保存額外報名 ID、event_id、名稱、profession_id、備註、有效狀態及 revision, 無 UID 且不加入名冊；請假改為 active=false, 再報名沿用 ID, 保留已確認排表快照。
- 統一送出檢查有效職業、場次 revision 及 requestId, 同一交易保存變更與重試回應；舊 API 保留相容, 不刪除既有資料。送出失敗保留輸入, 過期版本須重新載入後再送出。
- 報名／請假使用 expectedParticipant 的單人版本與資格檢查, 不再以場次 revision 或整場雜湊阻擋, 詳見下方「報名的單人版本與安全重試」。
- 本機帳號密碼保護管理頁與 API；場次報名讀寫及相容舊 API 對三種戰鬥均開放匿名，有效登入寫入仍須 CSRF。場次專屬 participation-members 公開必要名冊選項；舊 calendar/members 與完整名冊仍須登入，其他管理權限不變。登入帳號未綁定 UID，選人／填名不作本人驗證，報名截止尚待定案。

## 已確認戰場排表規則

- 一般／專注排表提供「下載 JPG」, 以目前顯示資料匯出固定 5400px 寬、基準高度 3771px 的完整三團十隊六十位置, 不受手機版型影響；圖片跟隨下載當下的深色／淺色模式，團別用紅／藍／綠實底隊名表頭與頂部圖例識別。職業／姓名／職責備註三欄，姓名中等粗細置中、職業一般粗細且文字對背景至少 3:1（大字），長姓名先縮字維持單行、空位顯示「—」、儲存格磁磚間隔、頁首單列；保留場次、實際選用職業、雙場標示及長文字完整換行；超出基準時增加高度、不裁切或壓扁內容，圖片左側顯示場次日期與星期幾（例如 2026-11-26（星期四））, 對戰標題以整張圖片為基準置中, 右側顯示團別圖例；依兩側內容實際寬度保留空間, 對戰標題放得下時維持單行、過長才換行, 不顯示已儲存／未儲存／已封存等操作狀態；省略重複欄名、位置小數字與「（副）」標記，不含 UID／側邊名單／操作控制。未儲存修改亦匯出且不自動保存, 封存沿用原快照；由瀏覽器 Canvas 產生, 失敗保留草稿並可重試, 不新增套件或後端寫入。

- 「成員來源」選擇本場外援時提供「代為報名」, 名稱／職業必填、備註選填, 只寫入當前場次；沿用統一報名的身分比對及版本／重試保護。成功更新來源並清除篩選, 既有成員切至所屬來源, 不清除未儲存排表或新增重複名冊；封存不提供報名。

- 導覽 `#/lineups`, 約戰／幫戰／龍虎戰共用進攻 3 隊、機動 3 隊、防守 4 隊, 每隊 6 個位置；一般活動不排表。
- 三種戰鬥皆可安排名冊所有成員（幫會、俱樂部、編外）而不必報名，以及本場外援（只報名本場的 registrationId）；排除本場請假人員。來源以下拉選單四選項切換：幫會成員、俱樂部成員、編外成員（UID 且非幫會非俱樂部，已報名者排前標示）、本場外援。
- 同一排表以 uid 或 registrationId 唯一且互斥引用, 第一／第二場皆可安排, 不替額外報名者產生假遊戲 UID；內部操作以不同命名空間區分。
- 約戰／幫戰／龍虎戰左側四類來源的合資格人員只顯示尚未安排者，第一／第二場任一有安排即隱藏，全部移出後恢復。本場請假成員／編外及已取消外援保留原分類並穩定排序在最下方，以淡化卡片及「已請假」標示，禁止選取／拖曳／主副職業切換；仍套用名稱／報名備註與主副職業篩選，不計入「尚未安排」。舊排表仍有請假者時也保留請假卡片提示，不自動清除草稿或放寬保存資格；更新名單清掉已失去資格的選取，取消請假後重載恢復正常資格。位置編輯保留完整合資格選項供調整／交換，不刪除成員或報名資料。
- 來源卡片主／副切換只設定本次安排偏好, 不修改名冊或已安排位置；點選／拖曳安排以偏好寫入既有 profession, 排表內拖曳保留原職業。無副職業及額外報名者只提供主職業, 按鈕不與成員選取按鈕巢狀。
- 拖曳及點選安排, 同位置第二人變第一場／第二場, 最多兩人且 UID 在兩場間不重複；第三人提示先編輯, 不覆寫。未指定第二場時沿用第一場, 明確編輯選人可交換該場分配。支援手機與鍵盤及各人主／副職業, 不要求填滿。
- slot.uid／profession 保存第一場, secondRound 可空保存第二場；姓名／職業快照、範本與資格檢查包含兩人, 舊缺值以 null 正規化但不改舊快照或 requestId 回應。總人數與占用位置分開計算。
- 範本獨立保存 UID 或報名 ID／位置, 套用時檢查現有資格、請假、職業與報名場次；其他場次或已取消的額外報名者留空並列出原因。
- 範本工具列只留「套用範本」與「範本」選單（存回這份範本／另存新範本／刪除範本）。`createLineupTemplate` 帶 `templateId` 時存回該範本（先確認），未帶但名稱相同時覆蓋最新一份同名範本（另存視窗先警告），皆保留 ID 與建立時間、回傳 `replaced`，並清除舊的成員參照覆寫。
- 排表首載使用 getLineupEditor（同次唯讀回傳場次、名冊／職業／職責與選定場次最新排表及參與），從四次整併一次；重新載入保留目前場次，失效時才選台北今天起最近場次。換場使用 getLineupEvent，一次回傳最新一筆與本場回應，封存不讀 participation，更新事件版本與封存狀態。舊 getLineupIndex／getLineupHistory 及完整歷史保留相容，畫面不再用來首載。
- 名單範本首次開選單才以 getLineupTemplates 讀 id／name／createdAt，不預載完整配置或做全部範本 UID 投影；成功只重用當頁，重新載入／離頁失效，錯誤可重試且不影響排表草稿。完整配置由原 applyLineupTemplate 於套用讀取，另存成功忽略較早的清單回應。來源更新／套用後更新名冊統一 getLineupSources，不讀排表或範本，保留既有草稿與預期保存版本。
- 每場直接載入最後保存的排表供編輯, 按「儲存排表」直接保存並保持可編輯, 不提供工作區／歷史版本切換或二次儲存確認；想保留配置時使用「另存範本」。顯示尚未儲存／有未儲存修改／已儲存, 離開或取代未儲存修改前提示, 不自動儲存。
- 後端沿用 lineup_versions 快照與 expectedVersion／eventRevision 檢查、防重複 requestId, 不刪除或轉換既有資料；版本僅作內部相容與並行保護, 介面不顯示版本流程。快照由後端取得當時姓名／職業／色彩, 不信任前端快照。
- 刪除或改類型的場次保留最後儲存的排表, 封存唯讀且可另存範本；lineup_templates 獨立保存可套用配置, 不自動把既有版本轉為範本。
- 職責清單使用 duties 獨立表, 固定 ID、唯一名稱、啟用狀態與 revision；初次建立保鑣／山盟／輔潮, 後續可新增、改名、停用／啟用, 重啟不覆寫。
- 成員／職責分配使用來源分頁；職責可拖曳或點選, 每位置多選且不重複, 同一職責可分配給多人, 空位也能預先規劃。
- dutyIds 屬於位置, 成員移動時職責與備註留在原位；確認快照由後端保存當時名稱, 停用／改名不改歷史, 範本套用跳過停用職責並提示位置。
- 舊版缺 dutyIds 視為空陣列, 不轉換舊備註或修改不可變快照；舊 requestId 仍可安全重試。

## 行事曆可見性與登入入口

右上登入預設「成員登入」，管理者可切換「管理者登入」。首頁一般活動、約戰、幫戰與龍虎戰均公開可見；三種戰鬥皆可匿名報名／請假、選取成員及上傳影片。GET /api/events 不再依 session 隱藏幫戰／龍虎戰；管理頁、完整名冊、出勤閱覽與影片閱覽仍沿用原角色限制。

報名視窗不含登入表單，三種戰鬥都有「直接輸入名稱／幫會成員名單／龍虎戰成員名單」。登入過期或撤銷後仍可使用公開場次操作；有效登入寫入維持 CSRF，登入狀態變動時重讀資料並拒絕過期回應，不清除未送出草稿。

## 已確認場次影片規則

- 行事曆第三個 tab「影片上傳」的名稱來源分為直接輸入／幫會成員名單／龍虎戰成員名單，選人帶入主職業且可改；角色名稱及職業必填。保留第一場網址（選填）、第二場網址（選填）、團別、備註（選填）與送出，兩場網址至少一個。來源切換保留網址／團別／備註，外層分頁與重新載入保留草稿。
- 名稱必填、兩場網址至少一個；三種戰鬥皆可填兩場。團別顯示為進攻團／機動團／防守團，備註最多 500 字並支援換行。只接受 HTTP／HTTPS，不接收檔案、不顯示 UID、不修改名冊／報名／排表。
- 一次保存一筆雙場提交，同名、相同網址可多次新增，不合併或覆寫。
- 切換外層分頁／重新載入保留草稿，成功清除表單、失敗保留，關閉有未送出資料先確認。
- 三種戰鬥皆可匿名送出影片；有效登入修改仍檢查 CSRF。職業由後端驗證並保存當時名稱／色彩，選單成員驗證目前姓名及所屬狀態；手動填名／選人不作本人認證，舊影片職業顯示「未記錄」，不回填推測值。
- 影片閱覽首載／重新載入使用 getVideoBrowser／GET /api/videos/browser?eventId=，同一唯讀快照帶戰鬥清單及選定本場影片，一次 API 呼叫；有效優先場次保留，否則沿用台北今天或最近過去、其次未來的排序。換場使用 getVideos，一次本場讀取。兩個讀取入口均接受 page（預設1）、limit（預設20、最多200）、search（名稱子字串、不分英文大小寫）與 group（團別）；SQL 合併新舊影片後依 createdAt 降冪、id 升冪分頁，回傳 videos／total／page／limit。CSV 按相同篩選逐批200筆讀完整結果，不只匯出當頁。
- 閱覽資料為當頁不可變 shallowRef，重載／換場／換頁／篩選時取新資料，不跨請求快取影片。重載保留仍有效的場次／搜尋／團別，失效場次回退並重設篩選；離頁／過期回應丟棄。搜尋與團別變更回第一頁，過期結果不得覆蓋目前條件。正常不取寫入鎖，資料表由明確 migration 建立。
- 影片閱覽每列可由 admin／manager「修改職業」，PATCH /api/events/:eventId/videos/:videoId/profession，只接受 professionId／revision／requestId。職業名稱與色彩更新為選項快照，其他欄位／名冊／報名／排表不改；舊缺職業可人工補正，缺 revision 視0。單筆版本與安全重試均在原寫入保護內，未登入／member 不可修改，有效登入檢查 CSRF。選項首次開視窗讀共用職業 API；成功以回應替換當頁一列、不新增重載，CSV反映新值。衝突保留選擇並以 videoId 定位單筆重新讀取新版本，關閉／卸載忽略過期回應。
- 影片閱覽每列另有「更換場次」與紅色「刪除」, 給送錯天的影片改到正確場次或直接刪掉。更換場次用 PATCH /api/events/:eventId/videos/:videoId/event, 只接受 targetEventId／revision／requestId, 只改 event_id 並把 revision 加 1, 其他欄位不變；目標必須是另一個有效的單日戰鬥場次。重試結果存在 `0007_event_video_moves` 建立的 event_video_move_requests, 同一 requestId 換內容會拒絕。舊 event_videos 紀錄可一起換, 目標場次已有完全相同的舊紀錄時拒絕並建議刪除
- `0007_event_video_moves` 是增量 migration, 只新增 event_video_move_requests, 不改既有影片資料；部署前要先另行套用, 不然啟動檢查會擋下
- 刪除用 DELETE /api/events/:eventId/videos/:videoId, 只接受 revision, 確認視窗列出場次、名稱、團別與兩場網址；直接刪除資料列, 舊紀錄連同職業修正一起刪, 重複刪除回 VIDEO_NOT_FOUND。原上傳 requestId 重送只回原結果, 不會把影片建回來。兩個操作都只限 admin／manager 並檢查 CSRF, 成功後從本場清單移除該列
- `#/videos` 與清單 API 只供 admin／manager，member 可提交但不能查看。選場次後使用角色名稱／職業／第一場連結／第二場連結／團別／備註與操作欄，提供團別篩選及名稱搜尋；CSV維持六欄。
- 閱覽第一／第二場網址以完整可複製超連結呈現，另開分頁且設 noopener noreferrer，沿用 http／https 驗證，缺值為 — 不建立連結；不另設直接前往按鈕或內嵌播放器。表格容器在手機橫向捲動，提供載入／空資料／錯誤與重試，切換場次拒絕過期回應。
- 追加 `event_video_submissions` 保存雙場／團別／備註及職業快照，沿用 `event_video_requests` 防重試；舊 `event_videos`／團別／重試資料保留並整合，不按同名合併，未知團別或職業不猜測。
- 新影片提交以場次 ID 關聯, 不檢查場次 eventRevision, 改標題後仍可送出並保留補傳歷史影片；刪除或改為一般活動停止讀寫但保留資料。閱覽只提供上述職業更正，不提供其他內容修改或刪除影片。

影片閱覽提供「匯出 CSV」，依目前團別／名稱篩選與表格順序輸出六欄（含職業），不讀取其他場次。UTF-8 BOM 保留中文，備註換行及引號正確轉義，公式字首以文字保存；載入、錯誤或無符合資料時停用匯出，失敗可重試。

## 出勤與請假紀錄

admin／manager 可由管理總覽或手機選單進入 `#/attendance`。預設「行事曆」依台北日曆月份顯示有效請假, 同日同成員多場只顯示一次人數, 點日期後按場次列出原因。「紀錄表格」才顯示月份／活動／成員篩選, 僅列所選範圍有有效請假的成員, 一人一列, SQL 分組後每頁 25 人, 按姓名與 UID 穩定排序。第一欄只顯示姓名, 第二欄顯示當月有效請假次數（達關心門檻時才顯示提示）與所選範圍最近一次有效請假的日期／場次（日期降序、場次 ID 排序）, 不顯示出勤狀態或備註。已銷假不計次數、不作為最近一次請假, 第三欄為「看更多」

表格「看更多」可開啟右側抽屜, 以成員 UID 查詢跨月份的有效請假歷史, 每頁 25 筆。抽屜每場提供「銷假」, 沿用管理者取消請假的權限、CSRF、單人 revision 與 requestId 安全重試；允許活動結束後銷假, 過去日期不擋管理者取消。操作中停用重複提交與關閉, 失敗保留清單並可重新載入, 成功更新抽屜、表格與行事曆, 該範圍已無請假者不再列出。抽屜與當天名單均按需載入, 已取消的請假與已取消活動不列入有效次數。匿名與 member 不可讀取管理歷史；公開送出請假的回應只包含達門檻時的關心文案, 不回傳個人次數或歷史

實際出勤由 admin／manager 另外登記「已到場／未到場／未登記」與選填備註, 不以報名、請假或未回覆自動推定實際到場。按日期與成員保留 revision, 寫入需 CSRF／requestId 並重驗當前 Session；並行修改會拒絕過期版本。成員 UID 修正同步移動出勤關聯, 明確永久刪除成員時一併移除該成員的出勤列

請假仍直接生效。送出成功使用非阻塞 toast, 同場有效請假只計一次；取消請假後不計入。關心門檻按活動日期所在月份累計, 預設 3 次；admin 可在本頁「關心提醒設定」修改 0–100 次與最多 300 字文案, 0 表示關閉。達門檻時另顯示一則關心 toast, 不自動拒絕請假或發送額外外部通知。無可確認 UID 的外援不以姓名跨場次合併計數

`0005_attendance` 為增量 migration, 新增實際出勤、重試識別與請假設定, 不回填或更改既有報名／請假。原場次「出勤閱覽」仍維持既有報名／請假投影, 新頁的實際出勤另行記錄

## 場次清單讀取

`GET /api/events` 支援成對的 `startDate`／`endDate`（YYYY-MM-DD, 含首尾, 最多相差366天）、`limit`（預設200, 1–1000）、`offset`（預設0, 0–10000）, 回傳 `events` 與 `hasMore`。SQL 先篩選任一日期落在範圍內的場次, 按最早日期／建立時間／ID穩定排序後分頁；回應保留該場完整日期供編輯。

月曆只查目前42格範圍, 切月重新讀取並拒絕過期回應。

活動管理使用 `GET /api/event-management`（僅 admin／manager）, 參數 `page`、`type`、`search`（最多64字, 名稱只折疊大小寫；無名稱的幫戰／龍虎戰以類型名稱比對）與 `focusId`。SQL 依最早日期新到舊、建立時間新到舊、ID 排序, 每頁20筆, 回傳 `events`、`total`（全部有效安排）、`filteredTotal`、`page`（超出時改為最後一頁, 帶 focusId 時改為該安排所在頁）與 `pageSize`。建立／修改後清除篩選並跳到該安排所在頁, 刪除後重讀目前頁。

戰績上傳選場與影片閱覽一樣使用 `GET /api/videos/choices`, 每批200場、最近場次優先, 用「載入更多場次」繼續；從其他頁帶入的指定場次不在第一批時另外讀單場。前端清單快取依日期與分頁參數區分, 保留一分鐘期限, 寫入與登入／登出清除所有範圍；最多保留24組查詢。

## 報名的單人版本與安全重試

公開報名／請假送出必須帶 `expectedParticipant: { person }`, `person` 是該次讀取中由 `participationTarget` 得到的單人識別、資格與回應 revision；尚無人員時為 `null`。後端在場次列鎖內重新解析並比較, 別人報名不影響此人, 同一人的過期修改回 `PARTICIPATION_CHANGED`。表單不再產生或傳送整場 SHA-256 revision, 也不傳場次 revision。

送出時依最新場次檢查：允許改標題後繼續送出；過去台北日期、非戰鬥類型、非單日或刪除的場次拒絕新報名／請假。低階成員回應及新增外援同樣檢查日期, 管理者取消請假仍可修正歷史紀錄。影片上傳保留歷史場次。

`requestId` 以資料庫唯一鍵原子登記, 同一 ID 與相同有效內容回傳第一次結果, 換內容回 `REQUEST_CONFLICT`, 失敗整筆回滾。取消請假也帶 requestId, 網路失敗重試沿用原 ID。低階舊 API 未提供 requestId 時僅依單列版本判斷衝突, 不再以 revision 恰好多一推測成功。

## 排表場次選項分批讀取

排表編輯器以單次批次 SQL 讀取場次選項，每批最多 200 場，依即將到來優先、過去由近至遠及標題／ID 穩定排序。`GET /api/lineups/choices?cursor=…` 僅 admin／manager 可讀，回傳 `events`、`hasMore`、`nextCursor`（不透明字串，沒有下一批時為 null）；前端由「載入更多場次」按需讀取，場次數量沒有上限。`/api/lineups/editor` 同步回傳分頁資訊，指定場次超出首批時另讀並保留選取，不影響下一批位置。封存場次只讀快照中的場次 metadata，完整排表仍按需讀取。

兩種選項以「日期階段＋日期＋標題＋ID」作為游標：每批先沿 `event_dates_by_date` 找出這批最後需要的日期，再只讀到該日期為止的場次並排序，讀取量約等於一批，不隨總場次成長。

## 影片場次選項分批讀取

`GET /api/videos/browser` 只讀取有效戰鬥場次，依最近場次優先、未來由近至遠與標題／ID 穩定排序，首批最多 200 場，回傳 `hasMore`、`nextCursor`。影片頁、更換場次視窗與戰績上傳以「載入更多場次」呼叫 `/api/videos/choices?cursor=…` 取得後續選項，不載入一般活動。指定歷史場次超出首批時另讀並保留選取，不跳過後續分頁；影片內容仍只讀選定場次。兩個入口維持 admin／manager 權限。

## 首頁已上傳影片名單

首頁場次的影片上傳新增第四個名稱分頁「已上傳影片名單」, 匿名與 member 也可查看。表格顯示「玩家」與「職業」, 一次載入本場完整名單、不分頁；玩家搜尋、職業篩選與職業欄升冪／降冪排序都在前端進行, 不新增 API 請求。職業缺漏顯示「未記錄」, 依職業排序時固定放最後, 同職業按玩家名稱排序。切換到名單與回到原輸入來源保留未送出的上傳草稿。

`GET /api/events/:id/video-names` 只回傳 `eventId` 與 `names: [{ name, professionId, professionName }]`。SQL 限定目前場次、合併新舊影片, 同名玩家維持一列並採最近一次上傳的職業快照, 不代表已驗證該成員本人。不回傳影片網址、備註、UID 或提交識別碼；完整影片閱覽 API 維持 admin／manager 專用。場次必須是有效的單日戰鬥, 不限制補傳歷史影片的日期。

每次開啟或按「重新載入名單」才取得目前資料, 重載保留搜尋／篩選／排序；換場重設條件並讀新場次, 關閉或換場忽略過期回應。載入／空資料／錯誤與重試分開呈現。此入口依目前每場少量上傳者的需求回完整精簡名單, 不影響管理影片頁原本的分頁。

## 指揮設定

排表工具列與排表之間提供 指揮 區塊, 預設關閉；開啟後進攻與防守各自切換單／雙 指揮。進攻單 指揮 只顯示「進攻」, 雙 指揮 增加「機動」；防守單 指揮 顯示「防守」, 雙 指揮 分為「防守12」「防守34」, 最多四人。名稱直接輸入最多 64 字, 不要求名冊成員、UID 或報名資格, 允許尚未填名。關閉區塊或切回單 指揮 保留隱藏欄位草稿, 不在畫面或下載圖顯示隱藏人員。

`0009_lineup_ob` 增量 migration 只新增 `event_lineup_ob`, 以自身 `id` 為主鍵、`event_id` 為唯一活動關聯。其餘 `enabled`（on／off）、`attack_mode`／`defense_mode`（single／double）、`attack`／`mobile`／`defense12`／`defense34` 都是純字串, 不關聯名冊。既有排表沒有 指揮 時視為停用。

指揮 與「儲存排表」在同一交易保存, 沿用管理權限、CSRF、場次 revision、排表 expectedVersion 及 requestId。版本快照另保留當次 指揮 純字串, 重試不重寫後來的 指揮, 版本衝突或任何寫入失敗不會只存一半。封存採儲存當時快照、禁止編輯；範本只處理原本隊伍配置, 不覆蓋當前場次 指揮。標準／專注排表共用設定, JPG 帶入目前啟用的 指揮 草稿, 不自動保存。
