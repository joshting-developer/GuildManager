# 帳號、品牌、等待與整合契約

本文保留既有產品契約, 供相關修改時按需查閱；實作協議另見 [Architecture](../Architecture.md), 介面依 [Style](../Style.md)。原文的版本、驗證及「尚未部署」敘述是當時紀錄, 不代表目前遠端狀態

## v2 初始管理員與歷史操作者

- v2 不沿用舊站的管理員帳號與密碼雜湊, 初始管理員統一使用 `admin`。實際密碼由私人 bootstrap 設定提供, 不寫進原始碼、範本、測試、卡片或前端 bundle
- 部署前明確建立 admin, 不在啟動時自動建帳號或重設密碼；使用既有帳號建立 CLI, 在受信任程序以 stdin 提供包含 `username`、`password`、`role: "admin"` 的私人 JSON。既有帳號仍拒絕覆寫, 不讓重新部署重設密碼
- 舊資料如果存在操作紀錄、建立者／修改者或其他管理帳號關聯, 匯入時統一對應到目標庫的 admin account ID。這個轉換只在歷史匯入邊界執行, 不設定成新資料的預設操作者
- 匯入後的新操作若有操作者欄位, 使用伺服器驗證的當前登入帳號, 不信任前端指定的帳號或一律歸到 admin
- 操作者轉換不影響遊戲成員 UID、報名者、戰績成員關聯、姓名或不可變排表快照；匿名操作不虛構登入身分
- 舊 Session 與登入限制計數不匯入。目前業務 schema 沒有操作人或稽核紀錄欄位, 不為了帳號替換新增稽核系統；將來匯入有這類資料時才套用上述規則

## 共用成員通行密碼

member 改為固定後端帳號，所有介面及登入回應隱藏名稱。admin 在帳號管理設定／修改 6–128 個英文字母或數字的通行密碼（區分大小寫，純數字仍可使用），初次不提供預設值，前導零保留。右上登入預設成員通行密碼；三種戰鬥的行事曆與報名均公開，報名視窗不提供登入表單。`POST /api/auth/member-login` 由後端指定帳號，與管理登入共用限流；`PATCH /api/admin/member-token` 須 admin、CSRF 及 revision。修改密碼撤銷共用 member 全部 session。舊個別 member 資料保留但不能再登入或沿用舊 session；舊新增／改名 member API 停用。admin／manager 密碼為 6–128 字元；包含 CLI 建帳號、初始設定與編輯器復原，長度不截斷，既有長密碼保留。

## 平台名稱設定

品牌快取依網站來源隔離, 只含公開名稱、圖示與 revision；先顯示快取並重讀最新設定。無資料先顯示占位，不閃出預設名稱；儲存／讀取成功才更新快取，圖示移除保存 null。快取毀損／受限／滿額不阻止操作，讀取失敗保留上次品牌並提供重試，不將快取 revision 用於授權或取代管理表單的最新設定。

admin 在帳號管理的「平台設定」分頁修改品牌名稱，預設「逆水寒」，1–30 個 Unicode 字元、trim、拒絕控制字元。僅 admin + CSRF 可修改，公開讀取只包含名稱、revision 與當前已保存圖示的 iconSrc（若有）。修改檢查 revision，可安全重試相同成功結果；MySQL `platform_settings` 保存。頂欄／頁尾／網頁標題同步更新，長名稱縮略且保留完整 title，不改 GUILD_NAME 或活動／戰績快照。

平台圖示支援 PNG／JPEG／WebP，最多 256 KB；後端檢查 MIME、Base64、實際大小與檔頭，前端另檢查可解碼及最多 4096×4096。選擇後先預覽，可移除／還原，名稱與圖示一次保存；成功更新頂欄，失敗保留草稿，重新載入或離開前提醒未儲存設定。本機追加可空圖片欄位，舊資料不改；替換／移除不自動刪除私人舊檔，跨服務未提交檔保留以便復原。

## 網站入口

網站直接掛載 App，保留非同步載入、DataLoading 與 PageLoadError（30 秒逾時），所有路由均可直接進入。

## 精簡品牌與導覽

頂欄保留平台名稱及 admin 已保存的圖示，不顯示預設圖示或「幫會管理平台」副標。member／manager／admin 的桌面與手機選單提供「回首頁」，點選後返回原行事曆首頁；點左上品牌亦可返回，保留登入／角色及未儲存離開保護。PlatformBrand 的可空 iconSrc 未提供時不渲染占位；圖示上傳與保存已實作，未整合 R2。

## API 等待介面

載入使用 src/components/DataLoading.vue 的轉圈與文字；減少動畫設定下保留靜態圖示。行事曆登入確認／讀取安排期間使用區塊遮罩及 aria-busy，完成前停用日期與月份操作，不先顯示空資料。API 選單等待時顯示進度且停用；戰績上傳讀取既有場序完成前不顯示尚未上傳卡片或表格。

登入送出只保留按鈕的一個轉圈，附近文字提供 role=status 提示；登入期間欄位、分頁與關閉停用。

儲存、匯入預覽／確認、刪除、報名／請假、影片、取消請假、歷史同步與有載入按鈕的清單更新，同次操作僅保留按鈕轉圈；DataLoading 以 spinner=false 保留狀態文字與 aria-live。混合讀檔／重新載入／套用範本的流程依是否有按鈕進度切換，無按鈕進度時保留預設轉圈，不讓等待狀態消失。

送出資料時保留草稿與原表單，使用局部進度、按鈕轉圈及原有停用／persistent／防重複規則，不加入全頁寫入遮罩、延遲或自動重送。失敗保留輸入，進度在成功／失敗後結束，載入失敗提供重試。

## 已確認抽獎活動規則（原抽獎賽馬）

- 2026/10/07 由 `../game` 的 Lottery 頁整併，2026/10/13 依使用者要求改名「抽獎活動」並拆成多玩法：頁面殼層 `src/pages/lottery/LotteryPage.vue` 管名單／獎品／結果，玩法元件登記於 `modes.js`，頁面以卡片選玩法。`#/lottery` 僅 admin／manager，桌面頂欄不放入口（避免導覽換行），由管理總覽卡片與手機抽屜進入；member／匿名不可讀寫。
- 單一抽獎名單：參加人員（去重、每筆 1–64 字、最多 500）與獎品（可重複、每筆 1–80 字、最多 200），頁面「編輯名單」每行一筆，可帶入幫會／俱樂部成員名稱，不寫入名冊。
- 名單修改檢查 revision；名稱仍存在的已抽獎品依順序保留 ID 與得獎者，其餘視為新獎品。
- 每個獎品跑一場，參賽者為尚未中獎的人；後端以亂數決定並先保存冠軍，前端只演出動畫，重整或中斷不改變結果。重抽同一獎品回傳原得獎者，所有人已中獎則拒絕。
- 玩法有賽馬與轉盤，皆只為演出：賽馬台詞與特效依角色（`src/domain/race-commentary.js`），比賽中顯示目前領先者、不顯示金銀銅牌；轉盤結局為虛驚、指針變長、指針彎曲、轉盤滑動、指針斷掉、格子交換、格子放大，機率相同且不連續重複（正常 0%，僅保留給預覽），最後一定指向已保存的得獎者。使用者要求翻轉時不調侃被跳過的人，結果視窗不提及。
- 「清空得獎紀錄」需確認視窗及 revision，保留名單；取代 game 的管理密碼 prompt。
- 抽獎資料由 MySQL `lottery_boards` 保存 JSON, 不發送 Discord 通知。

## 已確認 Discord 通知規則

- 2026/10/07 由 `../game` 的 DiscordWebhook 整併；game 的「去洗澡提醒」屬個人用途不搬入，舊程式註解中的 Webhook 網址屬憑證不得複製。
- 請假頻道：成員／外援請假、請假後改回報名、管理者取消請假；一般報名不通知。內容為場次（日期・類型・名稱）、玩家與當場職業、狀態，不含備註。
- 名冊頻道：新增、實際有變更的修改（含原名稱）、移至編外；CSV 匯入合併為一則摘要。名冊通知含 UID（管理情境）。
- admin 可在「Discord 通知」分頁設定、更換、移除與測試兩組 Webhook。網址只在後端儲存，API 只回傳 configured／revision；修改需 admin／CSRF 並在交易內重驗 Session，以 revision 防止覆蓋。未曾設定的頻道沿用環境變數；移除後明確停用，不回退環境變數。每次發送讀取最新設定，不需重啟。
- Webhook 預設使用後端 `DISCORD_WEBHOOK_LEAVE`／`DISCORD_WEBHOOK_MEMBER` 私有環境變數, 未設定即停用, 只接受 Discord Webhook 網址。錯誤只記固定分類與 HTTP 狀態, 不輸出網址、Token、例外原文、回應本文或玩家資料。未設定選填頻道維持靜默停用；診斷本身失敗不影響已保存回應。
- 通知只在 MySQL 成功提交後排送。失敗依下列重試規則處理，不影響原操作。相同 requestId 重試、無變更的修改與失敗請求不通知。
- 訊息關閉 mentions 並跳脫玩家輸入的 markdown。真實 Discord 送達尚待使用者設定 Webhook 後驗證。

- Node 通知沿用記憶體佇列與 best-effort 投遞。只對 429 重試一次, 依 retry_after 等待且最多 5 秒；其他 HTTP 錯誤、逾時或網路例外不自動重送, 避免結果不明時重複發送。fetch 不跟隨重新導向, 單次送出最多等待 10 秒
- 已提交的通知不因平台頁尾名稱讀取失敗而省略, 改用預設頁尾。通知同步拋錯、Promise 失敗與診斷紀錄失敗都不能改變已保存結果或阻止後續佇列；無效通知格式只記固定 FORMAT_ERROR, 不印原始內容
- Node 正常停機會在在途要求完成、MySQL pool 關閉後等待已排通知, 共用整體 10 秒停機期限。這不是持久化 outbox, 程序崩潰、強制終止或超過期限仍可能遺失未送通知, 不保證 exactly-once；如需更強的送達保證需另行設計與驗收
