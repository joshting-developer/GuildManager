# 成員幫派與俱樂部狀態

## 原始需求

成員清單與資料加入兩個 boolean：是否在幫派內、是否在俱樂部內；篩選選單加入俱樂部／幫派／不篩選。

## 理解、假設與待確認

- 兩個狀態獨立, 可同時為是, 也可同時為否。
- 清單顯示所有未移除的名冊成員, 沒有在幫派內也能留在清單, 供俱樂部篩選。
- 選俱樂部只檢查俱樂部欄位；選幫派只檢查幫派欄位；不篩選包含四種組合, 可與名稱／職業條件交集。
- 移除成員是將紀錄移出名冊, 與取消「幫派內」勾選分開, 保存資料與歷史。
- 既有未移除紀錄沿用先前在會狀態, 幫派內為 true；已移除紀錄為 false。俱樂部原本未記錄, 初值為 false (未勾選), 可編輯確認。
- 新增／四欄匯入預設已向使用者提出可選問題, 暫定幫派 true、俱樂部 false；等待回覆期間先處理驗證與資料契約；未收到回覆後已在進度訊息明確說明採此預設。
- 匯入仍為四欄, 既有 UID 跳過且不改狀態；四欄匯入恢復已移除紀錄時沿用其既有狀態。
- API 用 isInGuild、isInClub, SQLite 用 is_in_guild、is_in_club, 回應使用真正 boolean。
- 舊客戶端編輯未提供新欄位時保留原值, 不意外重設；有傳值時只接受 boolean。

## 步驟與驗證

1. SQLite 非破壞遷移、加入／編輯／查詢與匯入相容, 測試四種組合、嚴格 boolean、revision、移除恢復、重啟與遷移, 驗證後提交。
2. 清單狀態欄、新增／編輯勾選、三種篩選、文件；測試篩選交集、分頁重設、修改保存、匯入預設、失敗保留輸入、桌面／手機與鍵盤, 驗證後提交。

## 驗證範圍

- 隔離 SQLite 與本機瀏覽器, 不在現有 Docker 名冊建立測試成員, 不讀寫 Google 試算表。
- npm test、Docker 測試、一般及 GAS 單檔 build。
