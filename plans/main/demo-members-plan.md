# 一百位示範成員

使用者原始需求：「幫我建立80個幫會成員 20個俱樂部成員 幫會成員全都是俱樂部成員 這樣共100人的假資料」。

## 範圍與現況

- 沿用 main, 開始時工作目錄乾淨；本機 Docker API 已有 1 位成員, 不覆寫、刪除或改動既有資料。
- 新增 100 位示範資料：80 位 isInGuild=true、isInClub=true；20 位 isInGuild=false、isInClub=true。因此示範群體幫派 80 人、俱樂部 100 人, 原有名冊另計。
- UID 使用 DEMO-GUILD-001～080、DEMO-CLUB-001～020, 名稱標示「示範資料」。九種已確認職業循環分配, 主副職業不同；不虛構過去名稱。
- 提供手動執行的本機建立指令, 經既有成員 API 寫入；已存在的示範 UID 跳過, 不重設使用者後續編輯。應用程式啟動不自動加入假資料。
- 本次使用者明確授權寫入日常本機 SQLite, 是原「不播種假成員」規則的指定例外；不寫入 Google 試算表, 不新增活動、排表或歷史。

## 步驟與驗證

- [x] 再次執行新增 0、跳過 100；瀏覽器核對搜尋與幫派／俱樂部篩選, 隨本次工作提交。

## 結果

- `npm run seed:demo` 首次新增 100、跳過 0。SQLite volume 共 101 位成員, 保留原有 1 位。
- 示範成員唯一 UID 100 個, 幫派兼俱樂部 80 位、僅俱樂部 20 位、俱樂部合計 100 位；九種主職業皆有資料, 主副職業不同且有效, 未新增過去名稱。
- 寫入前透過 SQLite backup API 建立一致性備份 `/data/backups/demo-members-before-1791033927745.sqlite` (Docker volume)。逐表比對 13 張資料表, 除新增成員外所有原有列完全一致, 活動／排表／歷史皆保留。
- 重跑新增 0、跳過 100, 101 位成員的資料、revision 與時間逐筆相同。
- Chrome 實際頁面驗證搜尋「示範資料」100 位、幫派 80 位、俱樂部 100 位；搜尋 DEMO-CLUB- 為 20 位, 再選幫派無符合資料, 無頁面錯誤。預覽 `artifacts/demo-members.png` 忽略版控。
- `node --check tools/seed-demo-members.js`、`git diff --check` 通過。本次不修改 UI、API 或資料表, 以實際資料比對及瀏覽器篩選驗證, 未重跑完整應用程式測試或 build。
- 假資料與備份保存在本機 SQLite volume, 不提交資料庫；建立指令與規則納入 Git, 啟動不自動新增。
