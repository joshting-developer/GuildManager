# 成員與編外人員分頁

## 原始需求與理解

- 成員清單增加「編外人員」tab。
- 成員頁只顯示 isInGuild／isInClub 至少一個 true；編外頁顯示兩者皆 false。
- 採保留便利操作的方案, 原移除按鈕改為「移至編外」, 只將兩個狀態設為 false, 保留 UID、名稱、職業與歷史。
- 編外人員可透過編輯勾選任一狀態返回成員頁, 不建立重複 UID。
- 搜尋、職業與分頁保留；幫派／俱樂部選單只在成員頁顯示, 切換分類時重設該條件與頁碼, 避免編外頁被互斥條件篩空。
- 新增時依目前分頁設定預設：成員頁幫派 true／俱樂部 false；編外頁兩者 false。儲存後顯示對應分類。
- 四欄匯入仍以既有預設新增, 包含編外人員的既有 UID 仍跳過, 不覆寫；結果提醒新成員歸類。
- 以前 removed_at 隱藏的紀錄在相容遷移轉為兩者 false 並恢復可查詢, 更新 revision, 保留原始資料與歷史；新操作不再設 removed_at。
- 保留原 DELETE /api/members/:uid 與 removeMember 名稱作相容介面, 改為移至編外並回傳 { uid, member }。

## 步驟

1. 資料層移至編外語意、舊移除資料遷移、API 回應與測試, 驗證後提交。
2. 成員／編外 tab、移至編外確認、跨分類編輯／新增、篩選與空狀態、文件, 驗證後提交。

## 驗證

- 兩狀態分組完整互斥、移至編外保存歷史、stale revision 拒絕、重試／no-op、重啟與舊資料遷移不重設、失敗回滾。
- 匯入編外 UID 跳過不覆寫, 同 UID 新增仍拒絕, 編輯返回成員。
- 瀏覽器驗證切 tab、鍵盤、分頁重設、篩選、移轉後數量與焦點、失敗保留對話框、修改跨分類與新增預設、桌面／手機。
- 隔離 SQLite 測試, 不新增測試人員到 Docker 現有資料, 不寫 Google 試算表。
- npm test、Docker 測試、一般及 GAS build, GAS 實際資料層尚未串接。

## 進度

- 步驟 1：移至編外只清除兩個狀態, 回傳更新成員, 同版本重複操作不增加 revision；舊移除紀錄轉為編外, 重啟不重設編輯後狀態。
- 本機 50 個測試全部通過, 包含移轉完整資料保留、版本衝突、失敗回滾、相容遷移與編外 UID 匯入跳過。
