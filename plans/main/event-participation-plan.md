# 行事曆首頁、場次報名／請假與排表來源

## 原始需求與現況

使用者要求原首頁移到 magament, 新首頁直接顯示行事曆；點戰鬥日期可報名或請假。排表成員來源分幫會、僅俱樂部及額外報名三頁, 請假者排除。額外報名可無 UID, 使用獨立資料表紀錄場次、姓名、職業及自行填寫備註。

- 開始 main 工作目錄乾淨。現有 Vue hash 導覽、戰鬥每日獨立 event ID、會員 UID 排表、不可變歷史／範本需相容保留。
- 沿用單檔部署的 hash URL：新首頁 `#/`, 管理總覽 `#/magament` (依使用者拼字)。管理日曆保留建立安排, 首頁只查看及參與。
- 報名／請假依場次 ID 保存, 同日多場分開選；一般活動只顯示詳情。戰鬥包含約戰、幫戰與龍虎戰。
- 本機登入未串接, 暫以選擇成員填寫報名／請假, 額外報名填姓名、單一職業、備註。不把選擇姓名當成身分驗證, GAS 維持明確未串接。
- 已詢問資格與請假操作方式, 暫未收到回覆；依本次需求先採三種戰鬥皆可使用三類來源, 請假從成員清單選擇。資格改為在幫派／俱樂部, 或本場已報名的編外人員／額外報名者, 且未請假。
- 額外報名 ID 與遊戲 UID 分開保存, 排表第一／第二場支援兩種引用且唯一。只在原場有效；跨場範本跳過其他場的報名者, 保留當時歷史姓名／職業／備註。
- 請假／取消報名後, 新確認與套用範本重新檢查；既有歷史不可變, 已開工作區保留但提示無效人員。
- 新表採新增初始化, 不覆寫原成員、活動、示範資料、排表／範本。日常 Docker 更新前備份, 驗證写入使用隔離 SQLite。
