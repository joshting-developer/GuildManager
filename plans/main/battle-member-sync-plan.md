# 管理總覽歷史戰績同步

## 需求與規則

- 管理總覽加入小型次要「同步歷史戰績」按鈕，不增加功能卡片；只供 admin／manager。
- 預覽全名冊（含編外）的目前名稱與過去名稱，唯一 UID 才補上未關聯的戰績玩家列；同一 UID 重複名稱去重。
- 目前名稱／舊名只要跨 UID 重複均列為衝突，沒有任何優先猜測；已綁定或原快照有歸屬的不轉移，原 CSV／玩家數據不改。
- 預覽區分現在名稱／舊名對應、列出衝突與人數；確認時重新計算與核對 fingerprint，資料變動要求重讀。
- requestId 安全重試；SQLite 交易／GAS script lock 與提交標記保證整批一致。前台有讀取／送出進度、失敗保留預覽與重試、關閉焦點返回。
- 舊同名若未出現在名冊或名稱歷史，CSV 本身沒有 UID，無法辨識，預覽提醒管理者核對舊名。
- 新增／匯入／上傳的既有自動匹配規則維持目前名稱，本次舊名補關聯由管理者手動確認。
- 本次本機實作與生成 GAS，未授權自動執行正式資料同步或重新發布。

## 步驟與驗證

1. 共用比對計畫、SQLite／GAS 預覽及確認、API adapter 與權限；測試舊成員、舊名、跨 UID 衝突、既有綁定、版本變動、重試及部分失敗。
2. 管理總覽次要入口與共用預覽視窗；測試桌面／手機、鍵盤、載入、錯誤、重試與同步結果，執行完整測試及兩種編譯。
3. 更新規範與手冊說明／示範圖片，按完成步驟提交。
