# 本機團隊分析示範資料

## 需求與範圍

- 使用者要求只在本機將 100 位假成員換成現有戰績姓名，並排好對應陣容，讓團隊分析可實際預覽。
- 目標為目前運行的 Docker api／guild_data volume 內 `/data/guildmanager.sqlite`；工作目錄沒有另一份日常 SQLite。
- 只改 DEMO-GUILD／DEMO-CLUB 固定 UID 的示範成員姓名及職業，保留 UID 與 80 位兼屬／20 位俱樂部所屬狀態；既有非示範成員不修改。
- 使用我方名字優先，其他示範名額使用其餘 CSV 唯一姓名，不複製同名或虛構遊戲 UID。此所屬及分團僅供本機測試，不代表實際幫會身分或戰術。
- 原戰績、CSV、結果、活動日期／刪除狀態及已保存排表版本保留。多數已有戰績活動已刪除，僅為本機 fixture 追加對應示範排表快照，不恢復活動或改一般 API 權限。
- 不讀取帳號密碼、不同步 GAS、不修改正式試算表或部署。

## 步驟與驗證

1. 唯讀確認資料、建立完整 SQLite 備份；先在隔離備份副本演練。
2. 使用共用成員驗證及相同的名稱歷史寫入規則，透過既有戰績同步 repository 綁定姓名，追加示範排表；同一交易提交，可重跑而不重複寫入。
3. 驗證 UID／所屬／非示範成員及原快照不變、五筆分析四團均有玩家、第二場對應、foreign_key_check／integrity_check；必要時透過隔離本機頁面截圖檢查。
4. 回報可點開的戰績與資料備份位置，Git 僅提交此次操作紀錄，資料與角色名字不納入版控。

## 執行結果

- 已修改 100 位示範成員的名稱與主職業，副職業因 CSV 未記錄而清空；80 位幫會兼俱樂部／20 位僅俱樂部及所有 UID 不變。既有 1 位非示範成員完整保留。
- 現有 CSV 有 159 個不同姓名，其中我方有 75 個；優先使用我方姓名，再補其餘 CSV 唯一姓名，不建立重複名冊。
- 透過既有同步程序新增 280 筆玩家與成員關聯，未重新分配已有關聯；改名前的示範名稱留在名稱歷史。
- 四個場次各追加一份標示「示範」的排表，五筆戰績均可分析。三個已刪除場次僅追加本機快照，一個有效場次透過一般排表保存程序寫入；原排表版本與活動刪除狀態不變。
- 分團沿用目前分析規則：進攻團為進攻1、機動團為進攻2、防守1／2隊及3／4隊各一團。51 人場次為 16／15／10／10；第二場 60 人為 18／18／12／12；35 人約戰為 11／10／7／7。我方均無未歸類者，另一陣營維持未歸類。
- 備份位於 Docker `/data/local-fixture-backups/2026-10-05T09-37-43-945Z-before-team-analysis.sqlite`，已複製至本機 `data/local-fixture-backups/` 同名檔案；演練副本、報告及畫面截圖亦存於該忽略目錄，均不提交版控。
- 隔離副本先演練並驗證重跑新增／修改均為 0，再以單一交易套用日常資料。檢查原戰績、CSV、活動、回應、範本、所屬狀態及原排表未變，外鍵檢查無錯誤、SQLite integrity_check 為 ok。
- 使用 Playwright 操作實際本機 Vite 前端，API 指向準備後的隔離 SQLite 副本；確認四團人數、實際姓名／數值／百分比及第二場對應，無頁面錯誤。日常資料的帳號、密碼及 session 未修改。
- 本次僅調整本機資料與操作紀錄，未修改產品程式或同步 GAS，故不重跑已通過的產品編譯與完整測試。
