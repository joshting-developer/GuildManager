# 排表密度調整

## 需求與假設

使用者反映排表格子太大, 無法在一個畫面看好完整陣容。

- 工作目錄乾淨, 不更動排表資料與既有成員／職責功能。
- 桌面縮小團區／隊名／位置列及上方操作留白, 名稱與職業改同行；長文字保留完整資料, 可聚焦／開啟位置查看。
- 增加專注排表, 收起頁面導覽、標題與設定區, 保留場次資訊、來源清單與主要操作；退出恢復原畫面與焦點。
- 以 1366×768 的專注模式與 1920×1080 的一般模式作為全部 60 個位置同框目標；字體、瀏覽器縮放、文字長度可能影響可視密度。
- 小螢幕仍保留較大點擊範圍及單欄, 不用全頁 CSS 縮放或縮小手機表單。
- 桌面緊湊位置至少 28px, 一般主要按鈕／手機位置至少 44px, 依本次使用者密度要求調整原風格規則。

## 步驟與驗證

- [x] 排表版面、專注模式及長文字查看, 同步 Style.md。
- [x] 隔離資料瀏覽器驗證桌面全 60 位同框、拖曳／職責／鍵盤／模式切換／儲存, 手機無橫向溢出；一般與 GAS build, 差異檢查後提交。

## 結果

- 位置列由至少 76px 改為桌面 28px, 職業與姓名同行, 十隊保持 3／3／4 欄；專注模式收起導覽／設定並保留場次、來源與儲存。
- 隔離 SQLite 以 60 位測試成員及職責驗證：1920×1080 一般模式最後一列底部 1050px, 1366×768 專注模式最後一列底部 757px, 全部 60 個位置同框且無橫向溢出。
- Chrome 瀏覽器驗證模式進出及焦點／捲動恢復、修改保留、職責拖曳與鍵盤分配、成員交換、確認及歷史唯讀、長文字查看, 1024／768／390／320px 無橫向溢出, 手機編輯與路由離開恢復正常。
- 現有 76 項測試及一般／GAS 單檔 build 通過；GAS 編譯頁 Chrome 驗證正常顯示未串接訊息, 無 HTTP 回退或外部 JS／CSS 請求。
