# 活動安排

## 需求與假設

- 建立活動安排頁面, 類型選單為活動／約戰。
- 約戰必須恰好一天, 活動至少一天, 可選不連續的多天。
- 第一版保存名稱、類型及日期, 暫不加入時間、報名、對手或出勤功能。
- 首頁月曆顯示本機已保存的安排, 不加入假資料。
- 使用獨立活動與日期資料表, 保留舊版資料表, 不顯示舊示範活動。
- 日期為 Asia/Taipei 的 YYYY-MM-DD 日曆日期, 不以 UTC 時刻替代。

## 步驟

1. 建立 SQLite 活動／日期表、交易寫入與 HTTP API。後端檢查單日／多日規則、有效日期與重複提交。驗證後 commit。
2. 建立活動頁面、建立對話框、日期月曆選取與前端 adapter, 串接首頁月曆, 更新文件。驗證後 commit。

## 驗證

- 隔離 SQLite 測試單日、多日、非連續日期、無效日期、重複日期、重試一致性、交易回滾及重啟保存。
- 瀏覽器驗證建立流程、切換類型、錯誤保留輸入、首頁日期顯示、手機版與鍵盤操作。
- npm test、一般及 GAS 單檔 build, Docker 本機環境檢查。
- 不寫入使用者現有 SQLite 或 Google 試算表, GAS 資料操作仍待串接。

## 執行紀錄

- 開始時工作目錄乾淨, 分支 main。
- 步驟 1 完成：scheduled_events／event_dates、單日／多日驗證、同一 requestId 重試保護、交易與 HTTP API。
- 步驟 1 驗證：37 個測試全部通過 (含 6 個活動測試)。首次沙盒執行不允許監聽連接埠, 在允許本機監聽的環境重新執行通過。
