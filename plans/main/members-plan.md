# 成員管理製作計畫

## 原始需求

- 拔掉首頁的假數字, 改為「待開發」
- 建立成員清單, 支援加入、移除、修改名稱與職業
- 欄位：UID、名稱、主職業、副職業、過去的名稱
- 過去名稱使用另外一張資料表, 透過 UID 對應

## 實作決策

- UID 以文字保存, 加入後不可修改, 保留前導零與長 ID
- 名稱與主職業必填, 副職業可留空
- 使用者提供九個職業：素問、龍吟、碎夢、潮光、玄機、九靈、鐵衣、血河、神相, 依最新提供的 job_id 與 colorcode 保存
- 職業保存於 `professions`, 前端 selector 讀取 API 資料, 成員以職業 ID 對應, 未來新增職業不需改前端選項
- `members` 保存目前資料, `member_name_history` 保存改名前名稱與時間
- 名稱更新與舊名寫入使用同一 SQLite transaction, 未改名不新增歷史
- 移除採退會標記, 成員從清單消失但保留過去名稱；相同 UID 重新加入時恢復成員, 延續歷史
- 使用 revision 檢查過期修改／移除, 避免多人編輯互相覆寫
- 本機 API 支援資料讀寫, GAS 使用相同 adapter 契約但正式資料層仍待後續串接
- 首頁未實作的概況、活動與公告一律顯示「待開發」, 不繼續加入範例資料

## 步驟與提交

1. 更新需求記錄, 清除首頁示範呈現與自動播種, 提交首頁調整
2. 實作 SQLite 資料表、成員 API、名稱歷史與有意義的資料測試, 提交後端
3. 建立成員清單與操作表單, 完成瀏覽器及編譯檢查, 更新文件並提交

## 驗證

- 首頁不出現任何範例統計、活動或公告
- UID 精度、重複 UID、驗證錯誤、改名歷史、職業修改、過期版本與重新加入
- 寫入失敗不顯示成功, 使用者輸入保留
- 移除前確認對象, 對話框支援鍵盤與焦點返回
- 桌面與手機版面、搜尋、重新載入後持續保存
- 一般 build 與 GAS 單檔 build 成功
- 瀏覽器測試使用獨立 SQLite, 不留下測試成員到使用者資料庫
